getting started / install

Install

pinshelf ships as a single container with one volume. Anything that can run Docker can run it: a VPS, a NAS, a Pi on the shelf behind the router. If you'd rather not run a container, the same app deploys to your own Cloudflare account.

Docker Compose

Drop this compose file next to wherever you keep them, set the secret and the public origin, and bring it up. 

services:
  pinshelf:
    image: ghcr.io/nxplain-sh/pinshelf:latest
    ports:
      - "3000:3000"
    volumes:
      - pinshelf-data:/data
    environment:
      BETTER_AUTH_SECRET: [YOUR-SECRET]
      BETTER_AUTH_URL: http://[YOUR-HOST]:3000
    restart: unless-stopped

volumes:
  pinshelf-data:
$ docker compose up -d

Generate the secret with openssl rand -base64 32. The container runs the app on workerd with its database and backups under /data, and migrations are applied on start.

Deploy to Cloudflare instead

The same app runs as a Worker with a D1 database and an R2 bucket for daily backups. Use the deploy button, then finish the setup from your machine with make d1-create, make secret-put, make db-migrate-remote, and make deploy.

First run

  1. Open http://[YOUR-HOST]:3000. With no users in the database the login page shows the setup form.
  2. Create the single account. The first account becomes the owner; later signups are rejected.
  3. Save your first page from the add box, or with the extension shortcut.

The home list is your active bookmarks; archive holds the archived and trash views, tags renames and merges tags, and the toolbox button (bottom right) runs cleanup scans, suggests tag merges, finds duplicates, and asks the model about a page. preview on any row opens the page in a small window, re-served without scripts so framing blocks do not apply.

Behind a reverse proxy

Terminate TLS at your proxy and forward to the container port. The PWA needs HTTPS to install, so give it a real certificate rather than a self-signed one. Set BETTER_AUTH_URL to the public origin, or sign-in will redirect to the wrong host. 

[YOUR-DOMAIN] {
  reverse_proxy localhost:[PORT]
}

One port serves everything, so there is no separate health endpoint to route: forward the whole site to [PORT].

Backup & restore

On Cloudflare a cron writes a JSON snapshot of the library into your R2 bucket every day at 03:00 UTC, and the newest 30 are kept. Self-hosters create the bucket once with make r2-create. Settings → Backups can also write a snapshot on demand, list what exists, restore from one, or delete one.

Restoring is additive: missing bookmarks are added, existing ones are untouched, and trashed bookmarks come back trashed. The same JSON file can be restored through the normal import flow.

Docker has no cron, so the daily snapshot never fires. Use Settings → Backups → Back up now, and keep a copy of the pinshelf-data volume somewhere off the box — the local backup objects live in that same volume.

Stop the container before you copy the volume. A bookmark saved mid-tar is a bookmark you get to save again.

Browser extension

The extension is a WXT build for Chrome and Firefox. It saves the current page or a right-clicked link through the REST API using an API token.

  1. In pinshelf, open /settings and create an API token. The key is shown once.
  2. Click the extension icon, open its settings, and paste the token.
  3. Set the API base URL to http://localhost:3000 for local development, or to your instance's origin in production.

The popup shows the current tab's URL and title, comma-separated tags, a collection picker, a save button that reports saved or already saved, and an all tabs button that saves every open tab in the window. Right-click a page or a link → Save to pinshelf, and the toolbar badge flashes ✓ on success and ! on failure. Tabs whose url is already saved get a ✓ badge, checked on navigation only. Type pin plus a space in the address bar to search the library from the omnibox. Token and base URL are stored in browser.storage.local and never synced anywhere else.

Permissions stay narrow: activeTab, contextMenus, storage, tabs (open tabs for the all-tabs button and the saved-page badge), sidePanel, and host access to https://app.pinshelf.app/* and http://localhost:3000/*. No other origin is reachable.

Install the PWA

pinshelf ships a web app manifest and a static-asset service worker, so it installs from the browser on Android and desktop, and on iOS through Share → Add to Home Screen. The manifest starts at / in standalone display.

Installing needs HTTPS with a trusted certificate, which the reverse proxy setup above provides; localhost is the exception. The service worker caches only static assets — never HTML or API responses — so it never serves a stale page.

Configuration

Every install reads a small set of environment variables. BETTER_AUTH_SECRET is required and the container exits without it; the rest have defaults.

  • BETTER_AUTH_SECRET — signs sessions and API keys. Generate one with openssl rand -base64 32.
  • BETTER_AUTH_URL — the public origin, default http://localhost:3000. Set it to the address you actually open, or sign-in redirects to the wrong host.
  • PINSHELF_PORT — published port in compose.yaml, default 3000.
  • PINSHELF_DATA_DIR — where the D1 database and local R2 objects persist, default /data, the mounted volume.

The rest lives in Settings: API tokens for the extension and any other client, AI, backups, import, and export. The API has an interactive reference at /api-docs and an OpenAPI document at /api/openapi.json; every client-facing route takes Authorization: Bearer <token>. The same tokens work with the MCP endpoint at POST /mcp, so ChatGPT, Claude, and other MCP clients can search, save, and organise the library directly.

AI is bring-your-own-provider: set a base URL, model, and API key for any endpoint that speaks /chat/completions, including a local Ollama or vLLM. The key is stored in your database and never returned to the browser after saving. The toolbox proposes duplicate groups to trash plus tags, descriptions, and collections, merges near-duplicate tags, and can summarise a single bookmark from its snapshot or YouTube transcript; nothing is applied until you check it, and duplicates go to trash, not deletion.

Keyboard shortcuts

pinshelf is keyboard-first. These work across the app and are the same on macOS and Windows/Linux unless a shortcut names a modifier. 

cmd/ctrl + k   command palette
j / k          move down / up a list
enter          open
x              select
t              trash
a              archive
?              shortcut overlay
esc            close

Import & export

Settings → Import / export takes four formats, detected by content rather than file extension. Non-http entries such as bookmarklets are skipped, duplicates are skipped by URL, and imports never fetch metadata: titles and descriptions come from the file.

  • html — Chrome, Firefox, Safari, and Raindrop (Backups → HTML). Folders become collections nested as parent/child, TAGS become tags, <DD> lines become descriptions, ADD_DATE becomes the created date, and Raindrop's Unsorted folder maps to no collection.
  • csv — Raindrop export or a spreadsheet. Header-driven: url is required; title, note, excerpt/description, tags, folder/collection, and created (unix or ISO) are used when present.
  • enex — Evernote. One bookmark per note, using <source-url> when present and otherwise the first link in the body; note text becomes notes, <tag> elements become tags, and <created> becomes the created date. Notes without a link are skipped.
  • txt — one URL per line. A trailing title after the URL is kept; # lines are ignored.

Export writes a full JSON backup (including notes) or a Netscape HTML file for other bookmark managers.
